# CAS UI and F11 thumbnail lifecycle research

Verified public-source pass, 2026-11-04. This is repository research documentation, not a live GitHub Wiki page or a claim that the running game contains these defects.

Compared the existing live wiki at `50de549758f5af56de26e63deaf4757ee9b53757` and the published Nov 4 branch `apex/hitch-baseline-20261104` at [`0207f83718f609acdcc7456a3db800cfa3ceeeea`](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/commit/0207f83718f609acdcc7456a3db800cfa3ceeeea). The three cases below are narrower than the existing general cache/context advice. They identify concrete source behavior and regression seams, not instructions to replace ongoing implementation. Unpublished fixes and the loaded game build were not inspected. No game assets, active worktrees, or runtime sessions were accessed.

## 1. Operation 7 can publish after thumbnail invalidation

**Source evidence.** The final `current()` predicate executes before acquisition of `g_dataMutex`; the pixel and error maps are then assigned without rechecking. Cleanup increments the image serial and clears the maps under that mutex. The consumer swaps out pixels without a per-result context token. Therefore a worker paused after a true predicate can resume after cleanup and publish old-context data.

- [Operation 7, lines 993–1008](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L993-L1008).
- [Invalidation, lines 1556–1560](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L1556-L1560).
- [Context adoption and consumption, lines 1594–1621](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L1594-L1621).
- [Operation 11 already checks inside the publication lock, lines 964–966](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L964-L966), a relevant local comparison rather than a proposed new framework.

**Focused reproduction executed.** A C++ fixture compiled the published cleanup function and final publication statement with fake CPU mailbox data. A deterministic barrier paused the worker after its predicate evaluated true, ran cleanup, adopted a new context, then resumed it. Result: image serial 8 and active new context, but both old pixels and old errors were present. This proves that ordering in the fixture, not an observed in-game stale image.

**Regression acceptance.** Place the barrier at the real completion-publication seam. Invalidate while paused, then resume. Neither old pixels nor old errors may enter the current mailbox. Include selection change, identical part ID in a new context, and teardown variants. Validation and publication must use the same invalidation discipline; another check only at request admission is insufficient. Preserve accepted current-context results and error reporting.

## 2. Gallery resources have a different teardown path from library thumbnails

**Source evidence.** [ResetRenderer, lines 4186–4203](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L4186-L4203) clears resource/library/icon textures and the preview renderer, but not gallery textures, sizes, attempted IDs, or image context. [DrawGallery, lines 3858–3880](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L3858-L3880) clears those only when library hash plus query changes. With the same query/hash after a distinct device is installed, retained SRVs can still be submitted and previous attempted IDs can suppress image requests. These are retained COM objects, not necessarily dangling pointers. [Swap-chain selection, lines 4221–4248](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L4221-L4248) shows renderer reset during successor adoption; a successor need not imply a different device.

**Proposed Windows regression, not executed.** Populate a gallery SRV on WARP device A. Reset the renderer, initialize distinct device B, and reopen the identical query/library hash. Check the device identity of every drawable SRV. Require a valid upload on B or a reload path, bounded old-device references, and no permanent attempted-ID suppression. Add an image completion pending during reset. Use same-device swap-chain replacement as a separate control.

**Exact framework contract.** Apex's [vendored header](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/third_party/imgui/imgui.h#L1-L32) identifies ImGui 1.92.8. Its DX11 backend blob matches upstream v1.92.8, `6573d2742dbc396534de344368a4d8deef6581e0`; this is not an upgrade recommendation.

- [ImTextureRef, lines 350–379](https://github.com/ocornut/imgui/blob/8936b58fe26e8c3da834b8f60b06511d537b4c63/imgui.h#L350-L379) stores an application-supplied raw texture ID separately from backend-managed texture data.
- [DX11 draw, lines 319–321](https://github.com/ocornut/imgui/blob/8936b58fe26e8c3da834b8f60b06511d537b4c63/backends/imgui_impl_dx11.cpp#L319-L321) casts that ID to an SRV and binds it.
- [InvalidateDeviceObjects, lines 597–619](https://github.com/ocornut/imgui/blob/8936b58fe26e8c3da834b8f60b06511d537b4c63/backends/imgui_impl_dx11.cpp#L597-L619) visits backend-managed textures, not Apex's gallery map. Backend shutdown cannot be assumed to invalidate application-owned IDs.

Microsoft documents that [PSSetShaderResources retains references when binding](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-pssetshaderresources). This does not turn a raw ImGui draw-list ID into an owner before binding or recreate it for another device. Separately, [ResizeBuffers requires releasing direct and indirect back-buffer references](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-resizebuffers). That requirement is not a reason to discard every unrelated thumbnail on an ordinary same-device resize.

## 3. CAS authority recovery records an attempt before Begin is submitted

**Source evidence.** [Authority recovery, lines 138–164](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_authority_methods.as#L138-L164) records `held.attempted` before preparing the request. The [actual width-transfer request, lines 11–25](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_grid_width_main_request.as#L11-L25) returns null for zero scroller width/height. [Notification handling, lines 143–164](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_authority_consumer_methods.as#L143-L164) can enable another probe while preserving the authority hold. A later valid geometry with the same context/feed/view tuple then hits the attempted guard even though Begin was never called.

**Translated-method reproduction executed.** Used the repository's [fixture harness](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/tests/test_cas_catalog_authority.py#L65-L78), published authority methods and actual width-request body. Following a legitimate native-generation change, width was first 0, then 100 plus notification. Observed two context observations, one request preparation, zero Begin calls, recovery false, and blocked state retained. The existing suite produced 23 passes and one skip for an absent compiled Main fixture. Native ActionScript, AVM/GFx and the game were not executed. Audited method bodies and harness match the older Oct 26 snapshot byte-for-byte.

**Regression acceptance.** Distinguish pre-Begin preparation rejection from a failed or uncertain post-Begin outcome. After geometry becomes valid and an allowed readiness/notification edge occurs, require fresh owner validation and exactly one Begin. Preserve the [existing no-replay-after-Begin test](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/tests/test_cas_catalog_authority.py#L90-L95). Do not clear the entire authority hold merely because the UI resized.

Useful lifecycle entry points:
- [Prepare/reuse, lines 2–39](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_authority_consumer_methods.as#L2-L39): grid, feed and cell schema decide reuse; held state routes to recovery.
- [Lease validation, lines 49–87](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_workflow_methods.as#L49-L87): root/stage/panel, feed/cell class, Sim, household, form owner, generation, session and pending intents.
- [Native retirement/recovery, lines 166–198](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_grid_authority_methods.as#L166-L198): UI handles are retired; recovery requires fresh context and validation.
- [Disposal, lines 262–327](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/Source/CASUi/catalog_authority_consumer_methods.as#L262-L327): cancellation ownership and replacement-widget protection must survive any recovery change.

## Already fixed in the Nov 4 source; do not duplicate

The older library upload path overwrote raw SRVs without releasing the prior view and rejected replacement at capacity 60. The inspected Nov 4 snapshot already uses a scoped candidate and [library_texture::Install, lines 8–38](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/ApexLibraryTextureLifetime.h#L8-L38); [the uploader](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Source/TD1ApexD3D11Proxy.cpp#L1617-L1631) allows replacement of an existing key at capacity. The helper releases the prior view and rolls back failed insertion.

Existing [lifetime tests](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Tests/LibraryTextureLifetimeTests.cpp) and [WARP pixel-readback test](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/blob/0207f83718f609acdcc7456a3db800cfa3ceeeea/NativeOverlay/Tests/LibraryTextureWarpTests.cpp) are concrete regression entry points. They were inspected, not run in this research pass. Their presence is not proof of deployment or game qualification.
