**Checked 2026-11-04; public-source research only.** This adds concrete entry points to the existing [external CAS reuse map](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/wiki/External-CAS-Reuse-Map), [shared-index requirements](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/wiki/Integration%E2%80%90Research) and RA-P12. ## Implementations worth comparing

### LlamaLogic: current retained-stream reference

[Current inspected commit 4a3d576f](https://github.com/Llama-Logic/LlamaLogic/commit/4a3d576f0afb776aba783db561760afb5b5de8b7), October 29, 2026, declares package 5.3.0. It is the strongest recently maintained implementation found for this specific read path.

- [FromPathAsync and GetFileAccess, lines 148–194](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L148-L194) retain a FileStream and explicitly select read access with read-only sharing.
- [Initialization, lines 1647–1706](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L1647-L1706) reads the 96-byte header and declared index range, not all TS4 payloads. Its DBPF-v1 branch additionally reads a compression directory. [Index parsing, lines 2132–2214](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L2132-L2214) handles shared T/G/instance-high fields, offsets, size/compression flags and first-entry duplicate-key behavior.
- [FetchRawStream, lines 791–850](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L791-L850) selects a bounded stored-byte range. [Get/GetAsync, lines 970–1034](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L970-L1034) retain the index but reread/decompress the requested resource: **retained index is not automatic decoded-payload caching**. [GetRaw/GetRawAsync](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L1298-L1319) provide a raw-data route.
- This is locked seek-and-read, not independent positional I/O. Get holds an AsyncLock; [ReadOnlySubStream](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/ReadOnlySubStream.cs#L6-L99) uses the owner's shared cursor. [Dispose/DisposeAsync](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L748-L788) close the owner without visibly acquiring that resource lock. Coordinate disposal with outstanding readers rather than assuming concurrent close is safe.
- Stored-byte bounds do not supply a complete output budget. Get allocates using the index's decoded length; [RefPack](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/Compression/Gibbed.RefPack/Decompression.cs#L35-L80) also allocates from its embedded header. Add explicit byte/pixel budgets and a documented length-mismatch policy. Keep [Save](https://github.com/Llama-Logic/LlamaLogic/blob/4a3d576f0afb776aba783db561760afb5b5de8b7/LlamaLogic.Packages/DataBasePackedFile.cs#L2283-L2308), which loads all resources before rewriting, out of the read-only thumbnail route.

## Safe reuse of a verified package within one run

**Proposal, not an implemented fix or benchmark.** A process lifetime is not itself an immutability guarantee. Extend the existing [RA-P12 verified-resource contract](https://github.com/Herbertofury/TD1-Occult-Hybrid-Apex/wiki/Performance-Research#ra-p12-reuse-exact-verified-resource-batches-safely), without replacing its shared index or existing batch path.

1. **Acquire the object before verifying it.** For the Windows path, open an existing ordinary file for read access with `FILE_SHARE_READ`, excluding write/delete sharing. [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) documents sharing checks against existing handles, denial of incompatible writers or writable mappings, and sharing restrictions lasting until close. Failure to acquire this handle is an unavailable lease, not permission to silently weaken sharing and mark the package verified. Retaining it can block editors/updaters; use a bounded lease pool and an explicit release path.
2. **Hash, index and slice the same retained object.** Verify the expected package fingerprint and parse/validate its index through that handle. Bind fingerprint, DBPF version/index, physical-file identity and provider generation into one immutable lease. Retrieve compressed resource ranges through the lease, not a new pathname open. A stale expected fingerprint must invalidate/rebuild the affected index generation, never bless old offsets. Eviction, close, reopening or I/O failure ends this proof; reacquire and reverify once for the new lease. An owned immutable copy is an alternative only when the copy itself is validated against the expected fingerprint and indexed consistently.
3. **Keep identity and freshness separate.** [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) compares volume serial plus 128-bit ID for open-handle identity. It is not a content digest. [File-ID documentation](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information) warns IDs can be reused over time and 64-bit IDs are insufficient for uniqueness on ReFS. Do not trust a persisted file-ID-only cache after a handle is closed. [File timestamps](https://learn.microsoft.com/en-us/windows/win32/sysinfo/file-times) can be explicitly set and may not be final until writing handles close.
4. **Choose cursor semantics deliberately.** Rust's [Windows OpenOptionsExt](https://doc.rust-lang.org/std/os/windows/fs/trait.OpenOptionsExt.html) defaults to read/write/delete sharing; a plain retained `File::open` is therefore not the lease above. [Windows FileExt::seek_read](https://doc.rust-lang.org/std/os/windows/fs/trait.FileExt.html) accepts an absolute offset but changes the cursor and permits short reads. Do not mix it with unsynchronized cursor-based reads. Microsoft's [.NET RandomAccess](https://learn.microsoft.com/en-us/dotnet/api/system.io.randomaccess?view=net-10.0) offers thread-safe offset reads without advancing position; its [Read contract](https://learn.microsoft.com/en-us/dotnet/api/system.io.randomaccess.read?view=net-10.0) still permits partial reads. In either adapter, loop to the exact stored length or return a bounded truncation/error result. Do not close/evict while readers hold a lease.
5. **Do not substitute byte-range locks or event silence.** [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) explicitly does not stop mapped-view writes. [ReadDirectoryChangesW](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) may delay size/write notifications until caches flush; zero transferred bytes or `ERROR_NOTIFY_ENUM_DIR` requires reconciliation. [USN records](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records) can coalesce repeated writes and old records can be discarded. Track the [journal identifier as well as USN](https://learn.microsoft.com/en-us/windows/win32/fileio/using-the-change-journal-identifier), with a fallback for missing/discontinuous journals. These mechanisms trigger index reconciliation; they do not replace the retained-content proof.

Keep the package lease distinct from the catalog's winning-provider snapshot. A newly added higher-priority package can change a resource's winner even when the old package is byte-identical. Cancel or discard stale thumbnail completions by provider/index generation. Qualify network, cloud-synced and non-Windows filesystems separately; the Windows sharing contract is not automatically portable.

## Focused correctness and measurement fixtures

- **One admission, many resources:** through one successful lease request varied thumbnail TGIs repeatedly. Assert one admitted fingerprint/index generation and exact compressed/decompressed byte equality against a simple reference reader. Count full-hash bytes, index bytes, selected-payload bytes, opens, decompressions and cache hits separately. Application read counts are not physical-disk I/O or elapsed-time results.
- **Sharing and lifecycle:** use disposable files and a second process to test an already-open writer, writable mapping, attempted in-place write, rename/replace, lease release and reacquisition. A sharing failure must remain an explicit retry/defer state. Test cancellation and eviction while reads are pending, with no use-after-close or leaked handles.
- **Identity adversaries:** same-length changed bytes with restored timestamp; same path replaced; two hard-link paths; package moved between volumes; provider precedence changed while the prior package remains open. Neither object identity nor an unchanged timestamp may revive a closed lease's verification.
- **Read/index boundaries:** force 1–3-byte reads and premature EOF; sparse offsets beyond 2 GiB; checked offset-plus-length arithmetic; truncated index; duplicate keys; all supported compression flags; stored length different from decoded length; malformed compression and oversized declared output. Validate bounds before allocation, retain deletion/unsupported states, and enforce decompression byte/pixel limits.
- **Recovery:** inject watcher overflow, missed rename pairs, unavailable journal, changed journal ID and expired USN range. Publish only validated index generations; no partly refreshed provider set or image from a previous request may appear as current.

No game packages were read and no active agents were contacted. These are source-grounded investigation leads; the proposed Windows lifecycle fixtures and end-to-end latency comparison have not been run here.
